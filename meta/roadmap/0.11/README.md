the event path's constant allocation is visible in every run.

## Watch for

- **A benchmark is not a test and never gates on absolute numbers.** Machines
  differ; the ratio to the committed baseline on the same machine is the only
  thing that means anything.
- **The temptation to optimise the checked arithmetic away.** `arith.npk`'s
  guards are the library's central claim (PA-012) and they cost a compare and a
  divide per digit. If they show up in a profile, the answer is a better bound
  or a cheaper check — never removing one.
