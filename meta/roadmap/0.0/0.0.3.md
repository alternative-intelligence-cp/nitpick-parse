# 0.0.3 — the harness, part 2 — PLANNED

> **Scope:** the remaining stages, the self-check that proves the harness can
> fail, and the tree checks that diff the library against the documents
> describing it. **The self-check is the load-bearing half**: a suite that only
> ever agrees with what it is handed reports green while checking nothing.

## 1. Decisions taken at planning

- **P-16 — the exact-code rule from the start** (D-237, `specs/BUILD.md` B-7).
  The set of codes a rejection test reports must EQUAL the set its expectations
  name. The compiler ran the weaker subset rule for six cycles and found, when
  it tightened, that 17 of 131 files were reporting something nobody had
  asserted. Starting strict costs nothing; loosening later is impossible.
- **P-17 — the tree checks run on every full invocation**, including the three
  that currently have nothing to check. `check_no_raw_accumulate` over an empty
  `src/scan/` is the right answer and is what makes the check exist on the day
  the first accumulator is written — which is cycle 0.1, the very next one.
- **P-18 — `--only` prints, twice, that a filtered run concludes nothing**, and
  nothing is committed on the strength of one. The compiler's phrasing, adopted
  whole, for the same reason.
- **P-19 — a pending self-check case prints as pending, never as passing.**
  Three of the eight cases test stages that do not exist until 0.5 and 0.3
  (`roundtrip` ×2, `corpus`). They are written now, marked pending, and go live
  in the cycle that creates their stage — so the day the stage lands, the case
  is already written rather than remembered.

## 2. The stages added

| Stage | Tool | Passes when |
|---|---|---|
| `parse` | the compiler's `tools/parse_check` | every `.npk` in the tree accepted with no diagnostic, each once |
| `accept` | the compiler's `tools/check` | accepted in silence |
| `check` | the compiler's `tools/check` | refused with **exactly** the expected codes |

The tools come from the compiler's tree, built once per run from the pinned
checkout.

## 3. The self-check — the eight cases

`harness/selfcheck.py` constructs each case, runs the harness against it, and
requires a **failure**:

1. a `program` case whose `expect-exit` is wrong by one
2. a `check` case expecting a code the compiler does not report
3. a `check` case reporting a code no expectation names — the D-237 rule
4. a `parse` case that does not parse
5. a `check_no_raw_accumulate` violation planted in a scratch file
6. *(pending until 0.5)* a `roundtrip` case whose second parse differs
7. *(pending until 0.5)* a `roundtrip` case whose **trees match** but whose
   second print differs byte for byte — the case that proves
   `specs/TESTING.md` V-7 is doing work
8. *(pending until 0.3)* a `corpus` entry whose pass count is one too low
   **and** one too high

**Rule:** the self-check runs **first** in every full invocation.

**P-20 — `check_no_recursion`'s exceptions table starts empty and must stay
empty at 1.0.** Any entry needs a reason, and "the depth is bounded by the
grammar" is not one — a grammar does not bound what an attacker sends.
