# 0.0.4 — `src/core/` — PLANNED

> **Scope:** `limits.npk`, `Vec<T>`, `Bytes`, `SmallMap<K,V>`. The storage
> primitives PA-004 decided to own rather than import, plus the one file every
> named bound lives in.

## 1. Decisions taken at planning

- **P-21 — `limits.npk` comes first, before any container.** Every bound in
  `specs/SAFETY.md` §7 with the rule that set it, in one file, so that
  `check_constants_named` has an authority to diff against from the moment
  containers start wanting numbers. A bound scattered across call sites is a
  bound nobody can audit, and this library's bounds are its defence against
  hostile input.
- **P-22 — `Vec<T>`'s block is `wild`, its lifetime its owner's scope.** The
  alternative — a managed `buffer` reinterpreted per element — needs a `=>!` per
  access, which is the unchecked reinterpretation the compiler's 1.4.2 found
  five latent instances of. One `=>!`, in one file, checked once, is the shape
  that survives. **Every `Vec` has a `vec_free` and every scope that made one
  calls it**, or `exit 0` traps under D-151 — which is exactly the enforcement
  wanted.
- **P-23 — `Bytes` is the only allocating byte builder in the library.**
  `string_concat` allocates per call, and a writer emits thousands of small
  pieces: the compiler measured exactly this shape as quadratic in `npkg`'s
  first full run, seventeen minutes of fifty-six spent in the kernel. **Nothing
  in `nparse` builds output with `string_concat` in a loop**, and a tree check
  would be worth adding if it ever appears.
- **P-24 — `Bytes` is backed by `buffer`, not by `wild`.** A `Bytes` is
  per-parse scratch or per-write output, and its reclaim should be automatic:
  `buffer` drops at scope exit. The contrast with `Vec<T>` is deliberate and
  each is right for its lifetime.
- **P-25 — `SmallMap<K,V>` is an ordered linear scan over a fixed-capacity
  array**, and is not a hash map. Its sizes are tens, a scan over a contiguous
  array beats a hash at that size, and there is nothing to verify. **There is no
  hash map anywhere in the language or the prelude to fall back on** (O-N3), so
  this is the only container of its kind the library gets.
- **P-26 — every accessor's obligation is written now**, in the syntax it will
  take, as a comment, with a property test standing in
  (`specs/VERIFICATION.md` P-1). Deleting a comment marker in the compiler's
  cycle 1.5 is a smaller change than inventing the clause then.

## 3. `Vec<T>`

```nitpick
pub struct:Vec<T> = { wild T->:items; int64:count; int64:cap; };
```

| Function | Contract (written as a comment now) |
|---|---|
| `vec_init<T>(cap)` | `ensures result.count == 0 && result.cap >= 1` |
| `vec_reserve<T>(v, need)` | `ensures v.cap >= v.count + need` |
| `vec_push<T>(v, move T:x)` | `ensures v.count == old(v.count) + 1` |
| `vec_pop<T>(v)` | `requires v.count > 0` |
| `vec_at<T>(v, i)` | `requires i >= 0 && i < v.count` |
| `vec_set<T>(v, i, move T:x)` | `requires i >= 0 && i < v.count` |
| `vec_truncate<T>(v, n)` | `ensures v.count == min(n, old(v.count))` |
| `vec_insert<T>(v, i, move T:x)` | `requires i >= 0 && i <= v.count` |
| `vec_remove<T>(v, i)` | `requires i >= 0 && i < v.count` |
| `vec_swap_remove<T>(v, i)` | `requires i >= 0 && i < v.count` |
| `vec_clear<T>(v)` | `ensures v.count == 0` |
| `vec_free<T>(v)` | `ensures v.cap == 0 && v.items == NULL` |

**`vec_at` returns by value and is therefore for POD `T` only** — for an owning
`T` a copy is refused (TYPE-046), and the family reads through `v.items[i]` at
the site that knows the element's shape. This is the compiler's own `List<T>`
note and the reason there is no generic `list_at` there either.

## 4. `Bytes`

```nitpick
pub struct:Bytes = { buffer:body; int64:len; };
```

`init`, `push`, `extend`, `extend_str`, `put_uint`, `len`, `view`, `take`,
`clear`, `free`. Growth doubles; `take()` hands the accumulated bytes out as an
owned `string`; `view()` hands a borrowed `uint8[]` for the write path.

`put_uint` writes decimal digits into a stack array backwards and appends —
allocation-free, because every writer emits numbers and `int_to_string`
allocates a `string` per call.

## 5. Steps

1. `limits.npk`, with the specification citation per constant. Commit.
2. `Vec<T>` with its suite: both `T` shapes, every accessor at its boundary
   (`i == 0`, `i == count-1`, `i == count`), growth from capacity 1 to 100 000,
   and a leak test that exits 0 so a missed `vec_free` traps. Commit.
3. `Bytes` with its suite, including the million-byte append with a bounded
   reallocation count (probe 11's shape, made permanent) and `put_uint` at 0, 1,
   9, 10, 99, 100 and `uint64` maximum. Commit.
4. `SmallMap<K,V>` with its suite, including the `EParseState` overflow. Commit.
