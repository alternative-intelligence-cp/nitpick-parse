## 2. The command

Until cycle 0.0.2's harness exists, a probe is built and run by hand, and `tools/env.sh` holds the three ways this plan
does it, each in one Bash call:

- `run4 <file>` — `npkc`, `llc`, `ld.lld` and the binary, at `-O0` and again through `opt -O2`, printing both exits;
  a file whose header carries `// mem-cap-mib: N` runs under that address-space cap, after a program that allocates
  nothing, built by the same toolchain, under the same cap — the control `PLAYBOOK.md` §9 asks for;
- `codes <file>` — `npkc` alone, printing each diagnostic's code and its `line:col`, which is a refused probe's verdict;
- `bill <file>` — the identities `NITPICK-REACH-003` names for a root that imports the file, which is what a consumer of
  it owes.

What `run4` runs for one probe, written out, from the probe's own directory, with `$NPKC` and `$NPKRT` the pinned
toolchain and `$A` this cycle's gitignored scratch:

```text
$NPKC probeNN_name.npk -o "$A/run4/p.ll"
llc -O0 -filetype=obj -relocation-model=static "$A/run4/p.ll" -o "$A/run4/p.o"
ld.lld -static "$A/run4/p.o" "$NPKRT" -o "$A/run4/p" && "$A/run4/p"; echo "exit $?"
opt -O2 -S "$A/run4/p.ll" -o "$A/run4/p.2.ll"
llc -O2 -filetype=obj -relocation-model=static "$A/run4/p.2.ll" -o "$A/run4/p.2.o"
ld.lld -static "$A/run4/p.2.o" "$NPKRT" -o "$A/run4/p.2" && "$A/run4/p.2"; echo "exit $?"
```

The flags are the manifest's `[toolchain]` lists (`nitpick.toml`), and `llc`, `opt` and `ld.lld` are LLVM 20.1.8 — the
version the compiler pins since its D-349, asked of the tools themselves, as block 0a does. Nothing is written under
`/tmp`. **A probe's exit status is read on its own line**, never through a pipe (`PLAYBOOK.md` §6).
