### 1.1 The tree it starts from

`tests/probe/` holds only its `.gitkeep`. The decision log holds 47 `### PA-` headings, the highest by value PA-103 —
the `base` the patches number from.

### 1.2 The compiler's text the patches cite, read at the pin

`TYPE_REFERENCE.md` §9.3 — "Enum values are plain i32 constants"; §9.2 — the read-only view is produced "by
`string_bytes`"; `MEMORY_REFERENCE.md` §5 — a stack overflow "enters the trap route as `StackExhausted` (4118)", and
the main thread's usable stack is 8 MiB; `DECISIONS.md` D-305 ("A stack overflow is a controlled trap") and D-351
(`string_bytes` returns the read-only view); the prelude's `pub error:StaleHandle = 4106i32;`. Each is a line block 0b
prints from `git show 7e91730:<path>`.

### 1.3 The literal envelope

`fixed uint64:BIG = 18446744073709551615u64;` is `NITPICK-LEX-004` at the literal: `UINT64_MAX` — and every `uint64`
literal above `INT64_MAX` — is outside the 64-bit literal envelope (the compiler's D-148), so probe 01b builds it as
`I64_MAX * 2u64 + 1u64`. `PLAYBOOK.md` §2 records the `int64` minimum's half of this; the unsigned half is new.

### 1.4 What a consumer of each module shape owes

`NITPICK-REACH-003` — a root importing one module and declaring no `failsafe` — names every identity the importer
owes (`PLAYBOOK.md` §6, the compiler as the oracle). Over four modules of the shapes cycles 0.1 and 0.4 will write,
written into scratch by block 0b:

| module | owes |
|---|---|
| a byte class (`b >= 48u8 && b <= 57u8`) | 6 — the floor: `Unreachable`, `HeapOom`, `HeapBadRequest`, `WildLeak`, `StackExhausted`, `MachineFault` |
| probe 01b's `mul_add`, guards and all | 9 — the floor, `DivByZero`, `DivOverflow`, `IntOverflow` |
| a cursor that indexes its `fixed uint8[]` | 7 — the floor, `OutOfBounds` |
| a function that makes and uses an `arena<T>` | 7 — the floor, `StaleHandle` |

PD-134 corrects `SAFETY.md` S-5, S-6 and §8 by these.

### 1.5 Where native recursion traps

Probe 10b's own program, its depth set by `sed`, at the four edges PD-133 states: 65 534 levels complete (exit 1, "no
`]` found") at both legs; 65 535 trap `StackExhausted` (106) at `-O0` and complete through `opt -O2`; so do 131 062;
131 063 trap at both. The edges were found by bisection at planning — about forty builds under the seat's lock — and
block 0b re-measures the four that bound them.

### 1.6 The shapes, over every `.npk` the patches add

`tools/shapes.py` blanks comments and string literals and counts the shapes the cycle README's landing list and
`PLAYBOOK.md` §2 name. Over its planted control it finds each shape it counts; over its clean control — every shape in
comments and strings around an ordinary program — only that program's three `exit` operands. Over the 28 `.npk` files
the patches add:

- **every `exit` operand is an `int32`**: 375 `int32` literals, four casts `(… =>! int32)` — the three size probes'
  exit codes and probe 08h's read byte (`=> int32`) — three `r.value` of a `Result<int32>`, and one `raw` call of a
  function returning `int32`. So the compiler's landing 104, which holds an `exit` operand to `int32`, moves none;
- **the only attribute names are `derive`, `Eq`, `Debug` and `Copy`** — at `7e91730` an unknown attribute is ignored
  (DEF-236 (d)), so a misspelling would pass in silence;
- **four plain `uint8[]`**, each a probe's subject: probe 08's fifth shape (a plain view of a fixed array, converting
  INTO a `fixed` slot) and three refusals that bind one on purpose (08d, 08f, 12c);
- and **none** of the rest: no valued enum variant, macro, held `@`, `give`, `fall`, `frac`, `NIL` field, `opaque`,
  `#wild_slice`, builtin named without a call, `stack` as a name, `.is_error ||`, or `failsafe` not opening with its
  `pick`.

### 1.7 The placeholders

No file the patches touch holds `@@PD-` as the tree stands, and the six the patches carry — PD-129 … PD-134 — each
have a line in `decisions.txt`, ranked from the base. No added line of any of the cycle's patches holds a bare label,
a number past the base, or a placeholder its step does not follow the declaration of: `apply.py` refuses each, on
every dry run and every application.

### 1.8 Every pointer the patches write

`tools/pointers.py` over the tree the patches leave: the 16 specification rules the added lines cite are each
defined there, and the sections they cite resolve — five in this repository's specifications, and the rest in the
compiler's or the workbench's documents, which §1.2 reads.

### 1.9 The flagship's mutants

Probe 01b's `mul_add` has four guards; each removed alone, on its own copy at planning, traps: no `acc > room` check —
93 (`IntOverflow`); no `digit > bound` check — 93 (the `bound - digit` underflows on the zero bound); no `base == 0`
check — 97 (`DivByZero`); the room computed as `bound / base` — 93 (the edge case overflows). So every guard of the
shape cycle 0.1's `arith.npk` inherits is load-bearing, and probe 01a is the fifth mutant: no guard at all.

## 2. The command

Until cycle 0.0.2's harness exists, a probe is built and run by hand, and `tools/env.sh` holds the three ways this plan
does it, each in one Bash call:

- `run4 <file>` — `npkc`, `llc`, `ld.lld` and the binary, at `-O0` and again through `opt -O2`, printing both exits;
  a file whose header carries `// mem-cap-mib: N` runs under that address-space cap, after a program that allocates
  nothing, built by the same toolchain, under the same cap — the control `PLAYBOOK.md` §9 asks for;
- `codes <file>` — `npkc` alone, printing each diagnostic's code and its `line:col`, which is a refused probe's verdict;
- `bill <file>` — the identities `NITPICK-REACH-003` names for a root that imports the file, which is what a consumer of
  it owes.

What `run4` runs for one probe, written out, from the probe's own directory, with `$NPKC` and `$NPKRT` the pinned
toolchain and `$A` this cycle's gitignored scratch:

```text
$NPKC probeNN_name.npk -o "$A/run4/p.ll"
llc -O0 -filetype=obj -relocation-model=static "$A/run4/p.ll" -o "$A/run4/p.o"
ld.lld -static "$A/run4/p.o" "$NPKRT" -o "$A/run4/p" && "$A/run4/p"; echo "exit $?"
opt -O2 -S "$A/run4/p.ll" -o "$A/run4/p.2.ll"
llc -O2 -filetype=obj -relocation-model=static "$A/run4/p.2.ll" -o "$A/run4/p.2.o"
ld.lld -static "$A/run4/p.2.o" "$NPKRT" -o "$A/run4/p.2" && "$A/run4/p.2"; echo "exit $?"
```

The flags are the manifest's `[toolchain]` lists (`nitpick.toml`), and `llc`, `opt` and `ld.lld` are LLVM 20.1.8 — the
version the compiler pins since its D-349, asked of the tools themselves, as block 0a does. Nothing is written under
`/tmp`. **A probe's exit status is read on its own line**, never through a pipe (`PLAYBOOK.md` §6).

patch, which `apply.py` STAGES, and each is committed at its block's end — exactly the staged files, with the dispatch's

## 9. What will bite

- **`stack` is a memory qualifier**, and a local of that name is `NITPICK-PARSE-002` followed by a claim that a brace
  is never closed, far from the cause (`PLAYBOOK.md` §10). The explicit stack's local is `frames`.
- **A `never fails` function's call is a `Result` unless it is called `raw`.** A size probe's `#size_of` is an
  `int64`: narrow it with `=>! int32` for `exit`, which landing 104 holds to `int32`.
- **A probe that compiles is not a probe that runs**: probe 06 is accepted by `npkc` and refused by `llc`. `run4` builds
  all four stages for exactly this reason.
- **A reference's wording of a diagnostic's site is not its site.** Every `expect-error-at` here is measured.
- **The size probes' exit codes are their sizes**, so a probe that fails an assertion exits with a code below 20 and
  one that measures a different size exits with that size — both are a difference from §6, and a stop.
- **Probe 09b allocates about 260 MB on purpose.** It runs under its 64 MiB cap; never uncapped.
